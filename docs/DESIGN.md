# Costr 设计原则与交互规范

> 本文档是 Costr 的 UI/交互"宪法"。**每开发一个新功能，必须先回看本文档和
> `docs/ui_demo.html`**，确认布局、配色、文案、信息密度、性能约束没有跑偏。
> demo 与功能实现同步更新——功能上线时 demo 里对应屏幕要改成真实效果，
> 下线的功能要从 demo 移除。
>
> 品牌名统一写作 **Costr**（首字母大写），不出现在 UI 上的技术词一律小写且只出现在本文档给开发者看。

## 1. 产品定位与用户

- **Costr = Chinese Nostr**：面向中国年轻用户的去中心化社交客户端。
- **目标用户**：用过 X（推特）、对去中心化技术几乎不了解的普通年轻人。
  - 他们要的是"另一个能用、好看、不卡"的社交 App，而不是"区块链科普读物"。
  - 因此技术名词（中继 relay、npub、NIP、kind）**一律不出现在主界面**，
    需要时用比喻说人话，详情见 §6。
- **平台**：Android / iOS / Windows / macOS / Linux 单代码库（Flutter）。
  - 移动端是主形态，桌面端是放大版，交互稿以移动端为准。

## 2. 设计优先级（冲突时谁让谁）

按以下优先级从高到低裁决冲突，**不能同时满足**时砍掉低优先级的：

1. **复刻 X app 的 UI 风格**（布局、信息架构、配色、间距、动作栏）——最高优先级。
2. **简约 / 年轻化**——少配置项、少装饰、大留白、克制用色。
3. **开箱即用**——默认值即最佳值，不给用户一堆开关去调。
   （唯一豁免：服务器节点自定义，见 §13——它是显式标注的高级功能，
   默认列表对绝大多数用户永远够用，只有服务器长期离线才需要动它。）
4. **性能**——省电、不卡、不 crash（见 §8）。
5. 个性化表达。

> 即：如果"简约"和"复刻 X"打架（比如 X 有某功能而它看起来不够"简约"），
> **优先复刻 X**。在复刻 X 的前提下尽量简约。

## 3. 视觉语言（X 风格基线）

### 3.1 Logo

- **形态**：一个圆角方块底（圆角 22%）+ 中间一个向右的"传播/广播"符号——
  由三条同心圆弧 + 一个圆点组成，象征"一条帖子从你这里向全网广播"。
  - 这是 Costr 核心隐喻：**你自己就是一个广播站**（对应去中心化的"没有中间平台"）。
- **风格**：单色线性描边（stroke，不填色），与动作栏图标同源——简约、年轻、与 X 的几何感对齐。
- **配色**：
  - 标志主版：黑 `#0F1419` 描边 / 透明底（浅色主题下）。
  - 反白版：白描边 / 黑 `#0F1419` 底（用于 FAB、启动页、深色块上）。
  - 不用渐变、不用多色——违反 §2 简约。
- **应用**：
  - App 启动图标：黑底白标志圆角方块（系统启动器里显眼且不花哨）。
  - 顶栏 logo：32px 高，标志 + "Costr" 字样（字样用粗体 17px，与 logo 描边同色）。
  - FAB：黑底白标志圆按钮（替代通用 ✏️ 图标，强化品牌）。
- **SVG 源**：见 `docs/ui_demo.html` 顶部 `<svg id="costr-logo">`，可直接复用到 Flutter。

### 3.2 配色

- **默认浅色主题**（X 浅色 = 纯白底）。深色主题后续版本再加，先做好浅色。
- 背景：`#FFFFFF` 主背景；`#F7F9F9` 次背景/分隔；边框 `#EFF3F4`。
- 文字：主 `#0F1419`；次 `#536471`；极淡（时间、handle）`#536471`。
- 主色/强调：**黑 `#0F1419`**（按钮、激活态——X 浅色主按钮是黑色）。
  - 放弃旧的 Material3 紫色 `#6750A4`（`theme.dart` 要改）。
- 危险/删除：`#F4212E`。成功/在线：`#00BA7C`。
- 通知红点：`#F4212E`。

### 3.3 字体

- 中文优先：`PingFang SC` / `HarmonyOS Sans` / `Noto Sans CJK SC` / `system-ui`。
- 正文 15px，名字 15px 600，handle/时间 13px 次色，标题 17px 700。

### 3.4 圆角与间距

- 头像 50% 圆；按钮/卡片圆角 16px；chip 圆角 999px（胶囊）。
- 帖卡左右 padding 16，上下 12；帖子之间用 1px `#EFF3F4` 分隔线（X 是细分隔线，不是卡片阴影）。
- 底栏高 56 + safe-area；FAB 圆形悬浮，主色黑底白字。

### 3.5 图标

- 线性描边图标，未选 `#536471`，选中 `#0F1419`（或填充版）。
- 动作栏四件套（参考 X 布局，Amethyst 交互）：
  - **💬 回复**：点 → push Compose 带 `replyTo`。
  - **🔁 转发**（弹菜单二选一，参考 Amethyst）：
    - **转发**（NIP-18 kind 6）：确认后签 kind 6 + `e`/`p` tag，直接转发不带评论。
    - **引用**（kind 1）：push Compose 带 `quoteOf`，正文带 `nostr:note1` 引用 + `e` mention tag。
    - 不做下拉即转发的隐藏入口——弹菜单让用户明确选，避免误操作。
  - **❤️ 喜欢 / Reaction**（点弹表情选择器，参考 Amethyst）：
    - 选择器分两区：**快捷 unicode**（❤️ 👍 😂 🔥 🎉 👎）+ **自定义表情**（NIP-30 `:shortcode:` + URL，按帖子上出现过的自定义表情优先展示）。
    - 选一个 → 签 NIP-25 kind 7（`e`/`p`/`k` tag + `emoji` tag for 自定义），列表下方 reaction chip 即时 +1；再点同一个 → 撤回（签 `-` content 的 kind 7）。
    - 帖子下方按 emoji 聚合显示 chip：`❤️ 18` `:nostr: 3`，我选中的 chip 高亮区分。
    - 不用 emoji 当动作图标本身（动作图标仍用线性 SVG）。
  - **↗ 分享**：复制 `https://njump.me/<note1>`。
- **右上角 `⋮` 帖子菜单**（参考 Amethyst）：
  - **复制帖子 id**：复制 `nostr:nevent1…`（NIP-19 nevent，带 relay + author hint），不是裸 hex——粘到别处或本应用发帖框都能解析回原帖。
  - **复制全文**：复制正文纯文本。
  - **⚡ 打闪（NIP-57 Zap）**：在「复制全文」下方，同等级菜单项。弹底部页：自定义聪（satoshi）数量 + 预设 chip（100/500/1k/5k/10k）+ 可选留言 → 解析对方 lud16/lud06 → LNURL-pay → 签 kind-9734 zap 请求 → 取 BOLT11 发票 → 二维码 + 复制发票 + 「在钱包中打开」（`lightning:` deeplink）。对方未配置闪电地址时提示「对方未配置闪电地址，无法打闪」。打闪＝zap，聪＝sat（文案统一中文）。
- **NIP-27 事件引用嵌入**：发帖框粘贴 `nostr:nevent1…` / `nostr:note1…` → 发布自动补 `e` mention tag（+ nevent 的 `p` author tag），正文保留 `nostr:…` 文本；渲染端把引用帖渲染成内嵌引用卡（作者头像+名+正文片段，点进 `/n/:id`），裸 bech32 文本剥离。

## 4. 信息架构（重新设计的导航）

X 风格底栏（4 tab + FAB），从当前 2 tab 升级：

| tab | 名称 | 图标 | 内容 |
|-----|------|------|------|
| 1 | 首页 | home | 顶栏 Costr logo + 全球/关注 切换（对标 X 的 For you / Following）+ 帖子流 |
| 2 | 搜索 | search | 全屏搜索页（用户 + 帖子结果），对标 X 搜索 |
| 3 | 通知 | bell | **本功能：通知中心**，全部/提及 tab + 通知列表 |
| 4 | 我的 | profile | 个人主页（banner/头像/资料/帖子/回帖/关注/关注者/收藏） |
| — | 发帖 | FAB(Costr logo) | 悬浮按钮 → 发帖/回帖/引用页 |

> 不放 X 的"消息(DM)"tab——Costr 当前只做公开帖子，不做私聊，避免出现空壳 tab。
> 以后真做 DM 时再加，届时同时更新本文档与 demo。

底栏用 `StatefulShellRoute.indexedStack`（已有），保持各 tab 状态。

## 5. 通知中心设计（本次重点）

### 5.1 数据来源（Nostr 协议映射，给开发者看的；用户界面**不出现**这些词）

| 通知类型 | 协议 | 订阅过滤器 |
|---------|------|------------|
| 回复我的帖子 | NIP-10 kind 1 | `{"kinds":[1],"#e":[我的note id…]}` |
| 提及我（@我） | NIP-10 mention | `{"kinds":[1],"#p":[我的pubkey]}` |
| 转发我的帖子 | NIP-18 kind 6 | `{"kinds":[6],"#e":[我的note id…]}` |
| 喜欢/表情 reaction | NIP-25 kind 7 + NIP-30 | `{"kinds":[7],"#e":[我的note id…]}`；聚合时按 emoji / shortcode 分组 |
| 引用我的帖子 | kind 1 含 `nostr:note1` | 客户端在 `#p` / 正文里匹配 |
| 新关注者 | NIP-02 kind 3 | `{"kinds":[3],"#p":[我的pubkey]}` |

- **订阅策略**：通知是 live 流（不 closeOnEose），但设上限缓存（见 §8）。
  - 我发过的帖子 id 是个集合，订阅 `#e` 用最近 N 条（如最近 200 条帖子），
    太老的帖子不再监听新 reaction，符合实际（老帖基本不再有人互动）。
- **聚合**：同一帖子多条 reaction → "A 和另外 3 人喜欢了你的帖子"（X 风格分组）。

### 5.2 界面

- 顶栏：标题"通知" + 右上 设置入口（⚙️）。
- 两个 tab（对标 X 的 All / Mentions）：**全部** / **提及**。
  - 不做 X 历史上的 Verified/Replies/Repost/Like 多 tab——太复杂，违反 §2 简约优先。
- 列表项（X 风格）：左侧圆形小图标（💬/🔁/❤️/📌/✨/👥）+ 头像组 +
  "谁 + 动作 + 你的帖子预览一行" + 相对时间。
  - 点 item → 跳到对应帖子详情 / 对方主页。
- 未读：**逐条**标记已读——点开某条（跳详情/主页）才把那条标已读，不再「进入页面整页标记已读」。未读项有稳定视觉区分（浅色背景底 + 类型图标下小圆点），点开后转已读、样式消失；底栏「通知」图标红点角标显示未读数（跨会话持久，未点开的不掉）。已读状态按账号持久化：**已读 id 集合 + 已读水位线**（「全部已读」/读到最后一条推进水位线，水位线及以下一律已读）——中继每次启动重推历史互动、id 集合有上限淘汰，只有水位线能保证老通知不「复活」。
- **双击底栏「通知」图标** → 定位到最上面一条未读通知并短暂高亮（未读在另一 tab 时自动切换）；无未读则回列表顶部。
- 空态："还没有通知。有人 @你、回复、喜欢你的帖子时会出现在这里。"

### 5.3 通知设置（开箱即用 + 少开关）

进设置页，**默认全开**，只给用户 4 个开关，每个开关下都有一句人话说明：

- 回复与提及（"别人 @你或回复你时通知"）
- 喜欢与转发（"别人喜欢、转发你的帖子时通知"）
- 新关注者（"有人开始关注你时通知"）
- 整合通知（"同一帖子的多条互动合并成一条，少打扰你"——默认开）

> 不给"自定义表情通知""中继选择""去重策略"这类技术开关——违反开箱即用。

## 6. 应用介绍页 / 新手引导

- **应用介绍页**（设置 → 关于 Costr）：logo + 一句话定位"更适合中文用户的 Nostr 开源社交客户端"，下方四张卡片，讲清核心优势与理念：
  1. **无审查（核心卖点，置顶）**：帖子分布在全球多台服务器上，没有任何人（包括 Costr 自己）能删除、封号、限流。
  2. **匿名（核心卖点）**：不绑手机号/邮箱、不实名，一串钥匙就是账号；配合代理上网更难追踪。
  3. **自托管**：私钥只在本机，不上传；没有公司能替你发帖或封你。
  4. **简单克制**：默认即最佳，开箱即用。
  - 页脚说明：Costr = 更适合中文用户的 Nostr 开源社交客户端；Nostr 是去中心化开放协议；代码开源可审计。
- **新手引导**（首次登录后一次性，可跳过）：3 步气泡 highlight——
  发帖按钮、通知 tab、关注一个人。后续不再弹。
- 所有说明文案**说人话**：不写"kind 1""NIP-19""中继"，写"帖子""你的身份""服务器节点"。

## 7. 账号：登录 / 注册 / 退出（参考 Amethyst）

Nostr 没有注册表——"账号"就是一对密钥。交互按此设计，不制造"用户名密码"的错觉：

- **入口**：登录页（首次 / 退出后）。两条路径，二选一，不强制流程：
  1. **创建账号**：本地生成 `nsec1` → **强制备份提示**（抄写 + 勾选"我已保存"才能继续），
     说明"丢失无法找回，没人能帮你重置"——这是去中心化的硬现实，必须前置讲清。
  2. **私钥登录**：粘贴 `nsec1` → 校验 → 存入 OS 安全存储。
- **创建账号是多步向导**（不是一屏完成）：
  1. **备份钥匙**：显示 `nsec1` + "复制私钥"按钮 + 红字警示"这把钥匙就是你的整个账号，
     丢失无法找回" + 勾选"我已抄写并妥善保存"（未勾选不能下一步）。
  2. **设置资料**：点头像（调相册选图，对应 NIP-92/Blossom 上传）+ 昵称输入框（≤20 字）。
     说明"以后随时能改，不填会用钥匙生成默认名"。
  3. **完成**：✓ + "欢迎，{昵称}！" + 提醒"私钥只在本机，设置→账号可再看"。
  - 步骤指示条（1·备份钥匙 / 2·设置资料 / 3·完成）顶部可见，当前步高亮。
  - 顺序锁死：必须先备份才能设资料——避免用户跳过备份。
- **退出登录**：设置 → 退出登录 → 确认 sheet。文案说清"本地数据保留，下次同钥匙可恢复"；
  并说明"没有彻底注销账号功能——去中心化里没人能删你的号，但你可以不再用这把钥匙"。
- **多账号（单活跃模型，参考 Amethyst）**：设置 → 账号区列出本机所有已登录账号，
  点按即切换（当前账号标「当前」徽标），长按移除，「添加账号」走登录/创建同一流程
  （`/login?add=1`，完成后回设置页）。任何时刻只有当前账号活跃——中继订阅、信息流、
  通知只属于当前账号，切走即断，不挂后台连接；NSFW 偏好 / 草稿 / 筛选随账号走，
  字号 / 主题 / 沉浸式等设备级设置跨账号共享。退出登录 = 移除当前账号钥匙，
  还有其他账号时自动切到下一个。
- 不出现"用户名/密码/邮箱/手机号"字段——误导用户。
- 不做"忘记密码"——直接在创建页讲清无法找回。
- 登录页用 Costr logo + 一句话定位（"你的广播站"），强化品牌。

## 8. 搜索 / 主页筛选 / 关注分组（Amethyst 参考）

- **全局搜索**（搜索 tab）：顶栏输入 + **帖子/用户 两个 tab**（Amethyst 风格，不做下拉混合）。
  帖子用 NIP-50 `search` 过滤器（中继 `nostr.wine`），用户用 kind 0 metadata。
- **语言过滤**（首页）：顶栏地球图标弹出菜单（全部 / 中文 / 英文 / 日文），过滤全球流和关注流的帖子语言。不在关注页/通知页/搜索页出现——只影响首页 feed。
- **首页关注下拉**（关注 mode，仿 Amethyst PeopleList）：关注 mode 顶栏 filter 图标弹菜单——**全部关注（默认）/ 各自定义关注分组 / 各关注的 #tag**，过滤关注信息流。默认 = 全部关注（与语言过滤一样开箱即用）。选中项持久化到本地 config（`following_filter`）重启保持，不上传中继。分组来自 NIP-51 kind-30000（已有 `FollowGroup`/`userGroupedFollowsProvider`，缓存优先），#tag 来自 kind-30015 兴趣集。**分组**过滤是客户端过滤已加载的关注流（即时、不发请求）；**#tag** 过滤则切换信息流来源——向默认池广播真实 `#t` 订阅（Amethyst 模式：`#t` 值带大小写变体，`kinds [1,6]`，`limit 100`，**不带 `since`**——标签帖稀疏，拿「已有最新」当增量起点会切掉全部历史；翻页按 `until` 回翻，首个 EOSE 只解锁界面、REQ 等所有中继 EOSE 才关），帖子可来自未关注的作者（旧客户端过滤只能看到已加载流里最近几天的带 tag 帖）。不支持 `#t` 的中继只是不返回结果，不影响其他中继。**同一套 `#t` 时间线也服务于「点帖子/主页上的 #标签跳到首页过滤」**（`tagFilterProvider`，任意 mode）：此前该路径同样只客户端过滤已加载内容，现与下拉标签共用 `tagTimelineFeedProvider` 真查中继；标签激活期间火水（全球）/ outbox（关注）暂停，事件按 mode 入窗口或内存库。
- **首页偏好持久化**：上次选的首页 tab（全球 / 关注）、语言过滤、关注下拉过滤重启后恢复——存本地 config 表（`feed_mode` / `language_filter` / `following_filter`），不上传中继。开箱默认即全球 + 全部语言 + 全部关注。
- **用户主页内搜索**：主页 banner 下方按当前 tab 就地过滤——
  帖子/回帖 tab 出现搜索框，按正文子串过滤该用户的帖/回帖（客户端过滤，不发请求）。
- **关注列表（我的关注 tab）支持二级视图**：
  - **关注的人**：顶部 chip 行：**全部 / 各分组**。选"全部"时按分组分段展示（每组带小标题 + 计数）；选某分组只列该组。搜索框按名字/handle 过滤。每行带"已关注"按钮，可就地取消关注。
  - **关注的标签**：标签 chip 网格，每个显示 `#tag + 帖子数`。点一个 → 跳到首页按该 tag 过滤；long-press → 确认取消关注；行首"+ 标签"可手动添加。
  - 两组之间用子 tab 切换（关注的人 / 关注的标签），不做下拉。
  - 分组对应 NIP-51 kind-30000（parameterized replaceable），已有 `FollowGroup`。
  - **关注的标签存储在中继**（NIP-51 kind-30015 Interests，`t` 标签列表，d=""），跨设备同步；本地缓存（`replaceable_events` 表）冷启动秒开，回前台不清空内存缓存（见 §10）。
- **关注者列表（关注者 tab）**：搜索框过滤 + 每行按钮——
  未互关显示"回关"、已互关显示灰色"已关注"。
- **收藏 tab（个人主页第 5 个 tab）**：每个用户主页都显其公开收藏帖（NIP-51 kind-10003 公开 `e` tag）；自己主页额外显私密收藏（`.content` 用 NIP-44 解密给自己）。UI 与关注页同款分组形式：顶部横滑 chip 行（**全部 / 公开书签 / 私人书签 / 各自定义分组**），选「全部」按分组分段展示（每组带小标题 + 计数），选某 chip 只平铺该组；搜索框按当前 chip 过滤。自定义分组读自 NIP-51 kind-30003 labeled bookmark lists（Amethyst 用作命名书签组），**只读展示**（分组管理下一批）。`bookmarksProvider` 缓存优先（先读 SQLite、后台 relay 刷新），每条用 `eventByIdProvider` 解析成 `EventCard`，加载中/不可用优雅降级。
- **关注自己（个人页，与关注他人一致）**：自己主页头像旁「关注自己」+「编辑资料」两个紧凑 icon 按钮同行对齐；"关注自己"走同一个多选分组弹窗 + NIP-02 路径，可把自己放进默认 + 多个自定义列表。设置页不再有"关注自己"开关。
- **新主题帖 vs 回复帖在 feed 中的区分**（X 风格）：
  - Feed 混合显示根帖和回复帖，不分开页面。
  - **根帖**：无前缀，正常展示。
  - **回复帖**：帖子上方显示 `回复 @用户名` 上下文行（带图标 + 灰色文字），用户可点击跳到原帖。
  - **引用帖**：帖子下方展示被引用帖的预览卡（头像+名字+内容片段），带"引用"标签。

## 10. 性能约束（设计阶段就要守）

通知中心最容易把 App 搞卡/搞耗电，因此硬约束：

- **订阅有界**：`#e` 监听集上限（最近 200 条帖子），超过淘汰最旧；通知缓存上限 1000 条淘汰最旧。
- **去重**：按 (来源事件 id, 类型) 去重；同一 reaction 不重复入列。
- **聚合优先**：列表渲染的是聚合后的 item，不是原始事件——
  100 条 reaction 聚合成 5 条 item，列表只画 5 个 cell。
- **批量更新**：通知到达不一条一条 setState，攒 300ms / 50 条 批量刷新一次（debounce）。
- **全球流门控重建**：全球是不间断 全量事件流，仓库每 200ms 批量 emit。点赞（kind-7）洪流
  不改信息流内容——信息流按 kind-1/6「内容修订号」门控重建，卡片计数/反应走单遍全局
  交互索引（每卡 O(1)，未变条目复用实例不重建），避免每 200ms 全仓库扫描 × 每张卡。
- **后台不订阅**：App 进后台暂停通知订阅（不持有 WebSocket），回前台再恢复 + 补拉增量。
- **后台不清缓存**：EventStore（非 autoDispose）与 relay pool 进后台不被清空，回前台只 nudge 断线重连 + 增量补拉，不做整页 reload——用户看到的 feed 保持不动。
- **不验签 全量事件流**：延续 v1 策略，通知流到达事件默认不验签（性能），可疑时再验。
- **图片**：通知里的头像/帖子缩略图用 `cached_network_image`，占位 + 错误回退，不因图崩。
- 这些和 `docs/CACHE_DESIGN.md` 的本地缓存架构一致——通知列表复用本地缓存读路径。

## 11. 视频播放（内联 + 全屏）

  底部 sheet 选择（横屏内容可滚，矮屏不裁档）。

- **交接**：内联 → 全屏携带播放位置与倍速；全屏页独立 controller（内联暂停），
  方向按视频自身宽高比锁定（竖屏视频竖着播）。

## 13. 服务器节点自定义（高级功能）

四类服务器（中继 / 搜索中继 / 索引中继 / Blossom 图床）在服务器节点页各自的
标题行右侧有「自定义」入口，打开底部面板编辑该类列表。设计约束：

- **劝退优先**：面板顶部固定警示区（warnBg/warnBorder），按类别说人话讲清
  ①这类服务器是干嘛的 ②「只有当某台服务器长期处于离线状态时，才需要来自定义」
  ③配错的具体后果（刷不出帖/发不出帖、搜不到、头像昵称不显示、图片上传失败）
  ④「不确定怎么改的话，保持默认就好」。图床额外注明「只支持使用 Blossom 协议的图床」。
- **数量钳制**：每类最多 10 台；下限中继 3 台（挂一台不至于全盲）、
  搜索/索引/图床各 1 台。达到下限时删除按钮禁用，达到上限时「添加」禁用。
- **暂存后一次提交**：面板内增删只改草稿，点「保存」才落库——一次持久化、
  一次连接池热替换、至多一次 kind 10002 发布。「恢复默认」同样只重置草稿。
- **全设备共享**：列表存本地 SQLite（设备级、不分账号），所有账号共用。
  仅「中继服务器」变更会以当前账号名义发布 kind 10002；非活跃账号在
  下次切换过去时比对「上次已发布列表」标记，有变化才补发，失败自动再试。
  图床变更纯本地（上传按列表顺序重试），不发任何事件。
- **改完即生效**：保存后连接池原地热替换（不重建池实例、不清信息流），
  页面立即重载列表并重新测速；发帖上传走新图床列表。

## 14. 服务器推荐与写成功率（节点自治配套）

自定义解决「怎么换」，这一节解决「换成什么」和「什么时候该换」。

- **为你推荐（去中心化发现）**：自定义面板打开即开始探测。候选不来自任何
  中心目录服务器，而是用户自己网络视图里已缓存的他人服务器列表事件
  （kind 10002 中继列表 / kind 10063 图床列表）聚合投票，再向已连中继发
  一次性有界 REQ 补冷启动样本。每个候选必须实测通过才显示：
  中继 = 可连接（临时 WS 探测）+ 免费（NIP-11 limitation/fees，无响应按
  未知处理、不排斥）；搜索中继还须 NIP-11 自我声明支持 NIP-50；
  图床 = 用当前账号实测上传一个极小测试文件（一次验证 Blossom 协议 +
  免费 + 不限白名单，未登录则只显示「登录后可为你推荐」）。索引中继本期
  不推荐——没有便宜可信的「收录所有人资料」判定手段。**找不到可推荐的
  就什么都不显示**（用户明确要求）；结果缓存 24h（空结果不缓存，避免
  网络一时不好把推荐藏一整天）。「换一批」是**滚动推荐**：去重只在一个周期
  内生效——已推荐过的 URL 记入轮转记忆（`server_reco_seen:<类别>`，持久化、
  封顶 50 条），刷新时排除以优先展示新面孔；可一旦没有「新的可推荐」服务器
  ——候选全都展示过、或仅剩的候选探测不通过——就回绕到最初那批重新循环，
  绝不因换尽而让用户长期看到空白（去重不是永久拉黑）。推荐只代表检测当时
  可用，面板文案
  提醒「更换后需自行验证可用性」，搜索中继（搜索效果无法自动检测）与
  索引中继（无推荐块，提醒并入劝退警示）尤重。推荐项一键「添加」
  只进草稿，仍需随其余改动一起保存。
- **写成功率统计（只统计写方向）**：发布时每台中继的显式裁决（OK 接受 /
  拒绝）记入该中继的最近 10 次样本（FIFO，SQLite config）。**超时不计**——
  发布走「任一接受即成功」的早返回，拿不到裁决通常只是慢、不是坏；真正
  死掉的中继由红色「离线」呈现。窗口内成功不足一半时，节点页该中继行
  标红提示「近期发送 N 次仅成功 M 次，建议更换」，点按直达自定义面板
  （与上面的推荐衔接：进去就能挑替代）。读中继不统计——能写入的中继
  几乎总能读，测读只会增加噪音没有信号。

## 15. 链接预览卡片（正文裸网页链接）

正文里的裸 `http(s)` 链接不再只是一行文字：探测一次服务器，按响应分流渲染。
这是内容渲染能力，不是新界面，不开设置开关（§2.3 开箱即用）。

- **分流规则**（`lib/services/link_preview.dart`）：
  - 响应 `image/*` / `video/*` / `audio/*` → 在原文位置渲染图片 / 视频播放器 /
    音频播放器（修复小红书式「格式只在查询参数里、路径无扩展名」的媒体链显示
    为文字的问题）。
  - 响应 `text/html` → 解析 Open Graph（`og:title/og:description/og:image/
    og:site_name`，回退 `twitter:*` → `<title>`/meta description），
    在帖子下方渲染预览卡；URL 文字本身保留可点。
  - 其余 / 失败 / 超时 → 保持原样纯文字链接。
- **候选范围**：只探测「裸」链接——排除媒体/文件扩展名（分词器已接管）、
  markdown 链接目标、imeta/媒体 tag 附件；每帖最多 4 个候选。
- **卡片视觉**（对齐 §3）：圆角 16、1px `border` 描边、无阴影；
  头图 16:9 铺满（`og:image`，加载失败整块收起降级为纯文卡——不因图崩）；
  标题 15px/w600 最多 2 行、描述 13px `text2` 最多 2 行、域名 13px `text3` 1 行；
  整卡点击外部浏览器打开（与链接文字点击行为一致）。
- **降级阶梯**：完整 OG → 无头图 → 纯域名卡。反爬墙（微博「Sina Visitor
  System」空壳页）的垃圾标题会被黑名单丢弃（标题与描述一起丢），
  绝不把「Sina Visitor System」当标题显示。
- **探测防护**（候选来自不可信帖子内容）：浏览器风格 UA、单次 8 秒超时、
  HTML 正文最多 128KB 且遇 `</head>` 提前停、≤5 跳重定向且每跳复查协议与
  内网地址（屏蔽环回/私网/链路本地/CGNAT/云元数据字面量）、图片视频只读
  响应头不下载本体、结果按 URL 会话级缓存（含负结果，防重复探测死链）。
- **性能**：探测只在卡片构建时（可见卡片）触发；折叠长帖只探测解析前缀里的
  候选；`FutureProvider.family` 会话缓存 + 家族内建在途去重。


## 16. 音频播放（内联）

帖子里的音频与图片/视频同为「媒体」，走同一条渲染管线（分词 → 段 → 组件），
只有播放引擎不同：`video_player` 官方不支持纯音频流（audio-only 源在 iOS 上
`initialized` 永不触发，flutter#75636），音频用专门的 `just_audio`（Android /
iOS / macOS 原生实现，与视频同底层谱系）。**不为桌面单造后端**：Windows/Linux
本来就没有视频播放实现，音频同样降级为「下载」文件 chip——桌面媒体播放的缺位
是同一件事。

- **识别**（`MediaAttachment.isAudio`）：imeta `m audio/*` / `["audio",url,mime]`
  tag 优先；无 mime 按扩展名（mp3/m4a/aac/wav/ogg/oga/opus/flac）。正文裸音频
  URL 与探测响应为 `audio/*` 的无扩展名链接（§15 分流）都在原文位置渲染播放器。
- **外观（Amethyst 式）**：跟随主题的圆角 16 + 1px 描边卡片（对齐 §15 卡片规范；
  不像视频恒黑——音频没有画面，卡片是界面元素不是「媒体表面」）。**波形条是
  主体**：imeta 带 NIP-A0 `waveform` 字段（空格分隔的幅度值，语音消息）就画真
  波形，否则按 URL 种子生成 96 根**合成波形**（基线 + 载波正弦 + 噪声 + 包络，
  同一条音频永远同一形状——Amethyst 用事件 id 做种子，costr 用 URL）。播放
  进度把波形条从左到右染色。
- **交互**：点播放才开始加载（懒初始化——信息流里音频卡可能很多，不能每张都
  预载）。控件**全部显式可点**：播放/暂停、±10 秒、真进度滑条（拖动暂停、
  松手 seek，与 §11 视频同纪律）、倍速（复用视频底部 sheet）、分享；波形条
  只作进度可视化（v1.2.3 曾让波形本身承担点按/拖动 seek，实测「没法点、
  没反应」，随即把控件全部提为显式部件，波形退为视觉标识）。
- **互斥与后台**：同一时刻最多一条音频在播（启动新卡先停其余）；App 切到
  后台（paused/hidden/detached）全部暂停——信息流音频跟随可见卡片，**不做
  后台播放服务**（用户预期：离开就停，想停随时停得掉）。
- **生命周期**：每卡一个 `AudioPlayer`，滚出可视树即 dispose（与 NetworkVideo
  一致）；未播放的卡零网络开销。
- **「代理媒体」覆盖音频**：显隐判定（`postHasMedia`）与代理加载把音频和图/
  视频同等对待。
- **发帖**：「音视频」入口（视频或音频，扩展名白名单 + 选中后按 MIME 校验兜底）；
  上传拿 `audio/*` imeta，发出即自动识别为播放器。上传期间三个入口禁用——上限
  只统计已入列附件，上传中再选会超出 9 图/单媒体/4 文件上限（已修）。


## 17. 地址引用（nostr:naddr1…）

正文里指向**参数化可替换事件**的地址坐标（kind + 作者 + d-tag，典型是 30023
长文）：与 NIP-27 引卡（`nevent1`/`note1`）**同一渲染契约**——原文剥掉实体，
文末追加嵌入卡。

- **解码**（`nip19.naddrDecode`）：TLV 0=d / 1=relay 提示 / 2=作者 /
  3=kind（4 字节大端）。d/作者/kind 缺一即 null；畸形 bech32 一律 null 不抛
  （不可信内容在渲染路径上不能炸）。
- **查找**（`addressedEventProvider`）：内存事件库 → 全球流临时窗口 →
  全池广播 `kinds+authors+#d`（与 id 查找共用同一套在途共享未来：去重、
  页面重建不重启）→ naddr 自带的 relay 提示（一次性 `fetchFromUrls`，命中
  落 SQLite 使重复刷到秒出）。
- **渲染**：帖子类（1/6/16/30023）→ 引卡样式（作者 + `title` tag 标题 +
  正文摘要，点按进帖子详情）；非帖子 kind（中继列表、应用配置等）→ 小标签
  「引用了类型 <kind> 的事件」；查无 → 「引用内容不可用 · 点击重试」；
  被屏蔽 → 屏蔽提示、点开才可见（均与引卡同款规则）。
