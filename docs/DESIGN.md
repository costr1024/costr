# Costr 设计原则与交互规范

> 本文档是 Costr 的 UI/交互"宪法"。**每开发一个新功能，必须先回看本文档和
> `docs/ui_demo.html`**，确认布局、配色、文案、信息密度、性能约束没有跑偏。
> demo 与功能实现同步更新——功能上线时 demo 里对应屏幕要改成真实效果，
> 下线的功能要从 demo 移除。
>
> 品牌名统一写作 **Costr**（首字母大写），不出现在 UI 上的技术词一律小写且只出现在本文档给开发者看。

## 1. 产品定位与用户

- **Costr = Chinese Nostr**：面向中国年轻用户的去中心化社交客户端。
- **目标用户**：用过 X（推特）、对去中心化技术几乎不了解的普通年轻人。
  - 他们要的是"另一个能用、好看、不卡"的社交 App，而不是"区块链科普读物"。
  - 因此技术名词（中继 relay、npub、NIP、kind）**一律不出现在主界面**，
    需要时用比喻说人话，详情见 §6。
- **平台**：Android / iOS / Windows / macOS / Linux 单代码库（Flutter）。
  - 移动端是主形态，桌面端是放大版，交互稿以移动端为准。

## 2. 设计优先级（冲突时谁让谁）

按以下优先级从高到低裁决冲突，**不能同时满足**时砍掉低优先级的：

1. **复刻 X app 的 UI 风格**（布局、信息架构、配色、间距、动作栏）——最高优先级。
2. **简约 / 年轻化**——少配置项、少装饰、大留白、克制用色。
3. **开箱即用**——默认值即最佳值，不给用户一堆开关去调。
4. **性能**——省电、不卡、不 crash（见 §8）。
5. 个性化表达。

> 即：如果"简约"和"复刻 X"打架（比如 X 有某功能而它看起来不够"简约"），
> **优先复刻 X**。在复刻 X 的前提下尽量简约。

## 3. 视觉语言（X 风格基线）

### 3.1 Logo

- **形态**：一个圆角方块底（圆角 22%）+ 中间一个向右的"传播/广播"符号——
  由三条同心圆弧 + 一个圆点组成，象征"一条帖子从你这里向全网广播"。
  - 这是 Costr 核心隐喻：**你自己就是一个广播站**（对应去中心化的"没有中间平台"）。
- **风格**：单色线性描边（stroke，不填色），与动作栏图标同源——简约、年轻、与 X 的几何感对齐。
- **配色**：
  - 标志主版：黑 `#0F1419` 描边 / 透明底（浅色主题下）。
  - 反白版：白描边 / 黑 `#0F1419` 底（用于 FAB、启动页、深色块上）。
  - 不用渐变、不用多色——违反 §2 简约。
- **应用**：
  - App 启动图标：黑底白标志圆角方块（系统启动器里显眼且不花哨）。
  - 顶栏 logo：32px 高，标志 + "Costr" 字样（字样用粗体 17px，与 logo 描边同色）。
  - FAB：黑底白标志圆按钮（替代通用 ✏️ 图标，强化品牌）。
- **SVG 源**：见 `docs/ui_demo.html` 顶部 `<svg id="costr-logo">`，可直接复用到 Flutter。

### 3.2 配色

- **默认浅色主题**（X 浅色 = 纯白底）。深色主题后续版本再加，先做好浅色。
- 背景：`#FFFFFF` 主背景；`#F7F9F9` 次背景/分隔；边框 `#EFF3F4`。
- 文字：主 `#0F1419`；次 `#536471`；极淡（时间、handle）`#536471`。
- 主色/强调：**黑 `#0F1419`**（按钮、激活态——X 浅色主按钮是黑色）。
  - 放弃旧的 Material3 紫色 `#6750A4`（`theme.dart` 要改）。
- 危险/删除：`#F4212E`。成功/在线：`#00BA7C`。
- 通知红点：`#F4212E`。

### 3.3 字体

- 中文优先：`PingFang SC` / `HarmonyOS Sans` / `Noto Sans CJK SC` / `system-ui`。
- 正文 15px，名字 15px 600，handle/时间 13px 次色，标题 17px 700。

### 3.4 圆角与间距

- 头像 50% 圆；按钮/卡片圆角 16px；chip 圆角 999px（胶囊）。
- 帖卡左右 padding 16，上下 12；帖子之间用 1px `#EFF3F4` 分隔线（X 是细分隔线，不是卡片阴影）。
- 底栏高 56 + safe-area；FAB 圆形悬浮，主色黑底白字。

### 3.5 图标

- 线性描边图标，未选 `#536471`，选中 `#0F1419`（或填充版）。
- 动作栏四件套（参考 X 布局，Amethyst 交互）：
  - **💬 回复**：点 → push Compose 带 `replyTo`。
  - **🔁 转发**（弹菜单二选一，参考 Amethyst）：
    - **转发**（NIP-18 kind 6）：确认后签 kind 6 + `e`/`p` tag，直接转发不带评论。
    - **引用**（kind 1）：push Compose 带 `quoteOf`，正文带 `nostr:note1` 引用 + `e` mention tag。
    - 不做下拉即转发的隐藏入口——弹菜单让用户明确选，避免误操作。
  - **❤️ 喜欢 / Reaction**（点弹表情选择器，参考 Amethyst）：
    - 选择器分两区：**快捷 unicode**（❤️ 👍 😂 🔥 🎉 👎）+ **自定义表情**（NIP-30 `:shortcode:` + URL，按帖子上出现过的自定义表情优先展示）。
    - 选一个 → 签 NIP-25 kind 7（`e`/`p`/`k` tag + `emoji` tag for 自定义），列表下方 reaction chip 即时 +1；再点同一个 → 撤回（签 `-` content 的 kind 7）。
    - 帖子下方按 emoji 聚合显示 chip：`❤️ 18` `:nostr: 3`，我选中的 chip 高亮区分。
    - 不用 emoji 当动作图标本身（动作图标仍用线性 SVG）。
  - **↗ 分享**：复制 `https://njump.me/<note1>`。

## 4. 信息架构（重新设计的导航）

X 风格底栏（4 tab + FAB），从当前 2 tab 升级：

| tab | 名称 | 图标 | 内容 |
|-----|------|------|------|
| 1 | 首页 | home | 顶栏 Costr logo + 全球/关注 切换（对标 X 的 For you / Following）+ 帖子流 |
| 2 | 搜索 | search | 全屏搜索页（用户 + 帖子结果），对标 X 搜索 |
| 3 | 通知 | bell | **本功能：通知中心**，全部/提及 tab + 通知列表 |
| 4 | 我的 | profile | 个人主页（banner/头像/资料/帖子/回帖/关注/关注者） |
| — | 发帖 | FAB(Costr logo) | 悬浮按钮 → 发帖/回帖/引用页 |

> 不放 X 的"消息(DM)"tab——Costr 当前只做公开帖子，不做私聊，避免出现空壳 tab。
> 以后真做 DM 时再加，届时同时更新本文档与 demo。

底栏用 `StatefulShellRoute.indexedStack`（已有），保持各 tab 状态。

## 5. 通知中心设计（本次重点）

### 5.1 数据来源（Nostr 协议映射，给开发者看的；用户界面**不出现**这些词）

| 通知类型 | 协议 | 订阅过滤器 |
|---------|------|------------|
| 回复我的帖子 | NIP-10 kind 1 | `{"kinds":[1],"#e":[我的note id…]}` |
| 提及我（@我） | NIP-10 mention | `{"kinds":[1],"#p":[我的pubkey]}` |
| 转发我的帖子 | NIP-18 kind 6 | `{"kinds":[6],"#e":[我的note id…]}` |
| 喜欢/表情 reaction | NIP-25 kind 7 + NIP-30 | `{"kinds":[7],"#e":[我的note id…]}`；聚合时按 emoji / shortcode 分组 |
| 引用我的帖子 | kind 1 含 `nostr:note1` | 客户端在 `#p` / 正文里匹配 |
| 新关注者 | NIP-02 kind 3 | `{"kinds":[3],"#p":[我的pubkey]}` |

- **订阅策略**：通知是 live 流（不 closeOnEose），但设上限缓存（见 §8）。
  - 我发过的帖子 id 是个集合，订阅 `#e` 用最近 N 条（如最近 200 条帖子），
    太老的帖子不再监听新 reaction，符合实际（老帖基本不再有人互动）。
- **聚合**：同一帖子多条 reaction → "A 和另外 3 人喜欢了你的帖子"（X 风格分组）。

### 5.2 界面

- 顶栏：标题"通知" + 右上 设置入口（⚙️）。
- 两个 tab（对标 X 的 All / Mentions）：**全部** / **提及**。
  - 不做 X 历史上的 Verified/Replies/Repost/Like 多 tab——太复杂，违反 §2 简约优先。
- 列表项（X 风格）：左侧圆形小图标（💬/🔁/❤️/📌/✨/👥）+ 头像组 +
  "谁 + 动作 + 你的帖子预览一行" + 相对时间。
  - 点 item → 跳到对应帖子详情 / 对方主页。
- 未读：进入页面后整页标记已读；通知红点只显示在底栏"通知"图标上。
- 空态："还没有通知。有人 @你、回复、喜欢你的帖子时会出现在这里。"

### 5.3 通知设置（开箱即用 + 少开关）

进设置页，**默认全开**，只给用户 4 个开关，每个开关下都有一句人话说明：

- 回复与提及（"别人 @你或回复你时通知"）
- 喜欢与转发（"别人喜欢、转发你的帖子时通知"）
- 新关注者（"有人开始关注你时通知"）
- 整合通知（"同一帖子的多条互动合并成一条，少打扰你"——默认开）

> 不给"自定义表情通知""中继选择""去重策略"这类技术开关——违反开箱即用。

## 6. 应用介绍页 / 新手引导

- **应用介绍页**（设置 → 关于 Costr）：logo + 一句话定位"更适合中文用户的 Nostr 开源社交客户端"，下方四张卡片，讲清核心优势与理念：
  1. **无审查（核心卖点，置顶）**：帖子分布在全球多台服务器上，没有任何人（包括 Costr 自己）能删除、封号、限流。
  2. **匿名（核心卖点）**：不绑手机号/邮箱、不实名，一串钥匙就是账号；配合代理上网更难追踪。
  3. **自托管**：私钥只在本机，不上传；没有公司能替你发帖或封你。
  4. **简单克制**：默认即最佳，开箱即用。
  - 页脚说明：Costr = 更适合中文用户的 Nostr 开源社交客户端；Nostr 是去中心化开放协议；代码开源可审计。
- **新手引导**（首次登录后一次性，可跳过）：3 步气泡 highlight——
  发帖按钮、通知 tab、关注一个人。后续不再弹。
- 所有说明文案**说人话**：不写"kind 1""NIP-19""中继"，写"帖子""你的身份""服务器节点"。

## 7. 账号：登录 / 注册 / 退出（参考 Amethyst）

Nostr 没有注册表——"账号"就是一对密钥。交互按此设计，不制造"用户名密码"的错觉：

- **入口**：登录页（首次 / 退出后）。两条路径，二选一，不强制流程：
  1. **创建账号**：本地生成 `nsec1` → **强制备份提示**（抄写 + 勾选"我已保存"才能继续），
     说明"丢失无法找回，没人能帮你重置"——这是去中心化的硬现实，必须前置讲清。
  2. **私钥登录**：粘贴 `nsec1` → 校验 → 存入 OS 安全存储。
- **创建账号是多步向导**（不是一屏完成）：
  1. **备份钥匙**：显示 `nsec1` + "复制私钥"按钮 + 红字警示"这把钥匙就是你的整个账号，
     丢失无法找回" + 勾选"我已抄写并妥善保存"（未勾选不能下一步）。
  2. **设置资料**：点头像（调相册选图，对应 NIP-92/Blossom 上传）+ 昵称输入框（≤20 字）。
     说明"以后随时能改，不填会用钥匙生成默认名"。
  3. **完成**：✓ + "欢迎，{昵称}！" + 提醒"私钥只在本机，设置→账号可再看"。
  - 步骤指示条（1·备份钥匙 / 2·设置资料 / 3·完成）顶部可见，当前步高亮。
  - 顺序锁死：必须先备份才能设资料——避免用户跳过备份。
- **退出登录**：设置 → 退出登录 → 确认 sheet。文案说清"本地数据保留，下次同钥匙可恢复"；
  并说明"没有彻底注销账号功能——去中心化里没人能删你的号，但你可以不再用这把钥匙"。
- 不出现"用户名/密码/邮箱/手机号"字段——误导用户。
- 不做"忘记密码"——直接在创建页讲清无法找回。
- 登录页用 Costr logo + 一句话定位（"你的广播站"），强化品牌。

## 8. 搜索 / 主页筛选 / 关注分组（Amethyst 参考）

- **全局搜索**（搜索 tab）：顶栏输入 + **帖子/用户 两个 tab**（Amethyst 风格，不做下拉混合）。
  帖子用 NIP-50 `search` 过滤器（中继 `nostr.wine`），用户用 kind 0 metadata。
- **语言过滤**（首页）：顶栏地球图标弹出菜单（全部 / 中文 / 英文 / 日文），过滤全球流和关注流的帖子语言。不在关注页/通知页/搜索页出现——只影响首页 feed。
- **首页偏好持久化**：上次选的首页 tab（全球 / 关注）和语言过滤重启后恢复——存本地 config 表（`feed_mode` / `language_filter`），不上传中继。开箱默认即全球 + 全部语言。
- **用户主页内搜索**：主页 banner 下方按当前 tab 就地过滤——
  帖子/回帖 tab 出现搜索框，按正文子串过滤该用户的帖/回帖（客户端过滤，不发请求）。
- **关注列表（我的关注 tab）支持二级视图**：
  - **关注的人**：顶部 chip 行：**全部 / 各分组**。选"全部"时按分组分段展示（每组带小标题 + 计数）；选某分组只列该组。搜索框按名字/handle 过滤。每行带"已关注"按钮，可就地取消关注。
  - **关注的标签**：标签 chip 网格，每个显示 `#tag + 帖子数`。点一个 → 跳到首页按该 tag 过滤。
  - 两组之间用子 tab 切换（关注的人 / 关注的标签），不做下拉。
  - 分组对应 NIP-51 kind-30000（parameterized replaceable），已有 `FollowGroup`。
  - 关注的标签存储在本地 config 表（不发中继）。
- **关注者列表（关注者 tab）**：搜索框过滤 + 每行按钮——
  未互关显示"回关"、已互关显示灰色"已关注"。
- **新主题帖 vs 回复帖在 feed 中的区分**（X 风格）：
  - Feed 混合显示根帖和回复帖，不分开页面。
  - **根帖**：无前缀，正常展示。
  - **回复帖**：帖子上方显示 `回复 @用户名` 上下文行（带图标 + 灰色文字），用户可点击跳到原帖。
  - **引用帖**：帖子下方展示被引用帖的预览卡（头像+名字+内容片段），带"引用"标签。
  - 个人主页的"帖子"tab 只显示根帖（kind=1 无 reply e-tag）；"回帖"tab 只显示回复帖。feed 不区分，混合展示。

## 9. 文案规范

- 全中文；品牌名 **Costr** 保留首字母大写。
- 相对时间：刚刚 / X 分钟前 / X 小时前 / X 天前（沿用现实现，措辞与 X 对齐用"前"）。
- 错误态说人话："暂时连不上服务器，下拉重试"而不是"relay EOSE timeout"。
- 配置项说明一句到位，不写技术文档。

## 10. 性能约束（设计阶段就要守）

通知中心最容易把 App 搞卡/搞耗电，因此硬约束：

- **订阅有界**：`#e` 监听集上限（最近 200 条帖子），超过淘汰最旧；通知缓存上限 1000 条淘汰最旧。
- **去重**：按 (来源事件 id, 类型) 去重；同一 reaction 不重复入列。
- **聚合优先**：列表渲染的是聚合后的 item，不是原始事件——
  100 条 reaction 聚合成 5 条 item，列表只画 5 个 cell。
- **批量更新**：通知到达不一条一条 setState，攒 300ms / 50 条 批量刷新一次（debounce）。
- **后台不订阅**：App 进后台暂停通知订阅（不持有 WebSocket），回前台再恢复 + 补拉增量。
- **不验签 firehose**：延续 v1 策略，通知流到达事件默认不验签（性能），可疑时再验。
- **图片**：通知里的头像/帖子缩略图用 `cached_network_image`，占位 + 错误回退，不因图崩。
- 这些和 `docs/CACHE_DESIGN.md` 的本地缓存架构一致——通知列表复用本地缓存读路径。

## 11. 文件维护规则

- `docs/ui_demo.html`：交互稿，单文件自包含（内联 CSS/JS）。
- `docs/DESIGN.md`：本文件，设计原则。
- 每次功能迭代：①改 demo ②改本文档对应章节 ③README 同步。
- demo 与实现**必须同步**——这是给后续开发（含 AI）防止跑偏的参照。
